body:
  en:
    - "A project may sit at an address different from the customer's — a 'differing project address' behind a toggle that defaults off. The tempting design was a persisted 'has own address' flag plus pre-filling those fields from the customer. Both were rejected. No flag is stored: whether a project has its own address is read from the data itself — all three fields empty means it uses the customer's current address, any field populated means it has its own. Projects created before this feature fall back transparently, and a toggle-off project always reflects the customer's address as it stands today."
    - "Story 058's separate 'intelli-fill' scope collapsed into this — the toggle-on fields reuse the address component that already carries intelli-fill, so 058 had no independent work left. The same restraint shaped creating an offer straight from a customer (Story 059): rather than eagerly spawning an empty project on click, project, positions and offer are created together in one transaction on the first valid save, so a cancelled flow leaves no orphan project behind. Such a project stores a null address and simply uses the customer's."
  de:
    - "Ein Projekt kann an einer anderen Adresse liegen als der Kunde — eine „abweichende Projektadresse“ hinter einem Schalter, der standardmäßig aus ist. Naheliegend wären ein gespeichertes Kennzeichen „hat eigene Adresse“ und ein Vorbefüllen dieser Felder aus dem Kunden gewesen. Beides wurde verworfen. Es wird kein Kennzeichen gespeichert: Ob ein Projekt eine eigene Adresse hat, wird aus den Daten selbst gelesen — sind alle drei Felder leer, nutzt es die aktuelle Kundenadresse; ist eines gefüllt, hat es eine eigene. Vor diesem Feature angelegte Projekte fallen so transparent zurück, und ein Projekt mit ausgeschaltetem Schalter spiegelt immer die Kundenadresse in ihrem heutigen Stand."
    - "Der eigene „Intelli-Fill“-Umfang von Story 058 ging darin auf — die eingeblendeten Felder nutzen die Adresskomponente, die Intelli-Fill bereits mitbringt, sodass für 058 keine eigenständige Arbeit übrig blieb. Dieselbe Zurückhaltung prägte das Anlegen eines Angebots direkt vom Kunden aus (Story 059): Statt beim Klick sofort ein leeres Projekt zu erzeugen, werden Projekt, Positionen und Angebot beim ersten gültigen Speichern gemeinsam in einer Transaktion angelegt — ein abgebrochener Ablauf hinterlässt so kein verwaistes Projekt. Ein solches Projekt speichert eine Null-Adresse und nutzt schlicht die des Kunden."
